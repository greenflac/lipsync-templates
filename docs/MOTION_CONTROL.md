# Архитектура: движение по реальному референсу

Статус: проект на утверждение владельцем, 2026-10-08. Кода под него нет.

## Задача

Движение в кадре должно быть настоящим. Модель видео сама рисует движение плавным, равномерным и «хореографическим», и зритель это считывает как фальшь.

Владелец, 2026-10-08:
- «движения в бою выглядят реально фальшиво»;
- «ускорение, замедление — это всё дополнительная фальшь»;
- нужно архитектурное решение на основе референсного контроля движения.

Значит, движение не придумывается моделью, а **берётся из записи реального человека** и переносится на наших персонажей. Лица, тела, форма, площадка и звук остаются нашими.

## Где это стоит в пайплайне

| Стадия | Что делает контроль движения |
|---|---|
| 2. Референсы | на каждое действие в сценарии ищется запись реального движения: эфир, стоковые записи, своя съёмка |
| 3. Декомпозиция | у каждой записи — число людей, ракурс камеры, длительность, контакт тел; недостача — действие без записи |
| 4. Реализация | этот документ + одна проба возможностей стека |
| 5. Раскадровка | владельцу показывается ключевой кадр **и скелет движения** плана; движение утверждается до дорогого рендера |
| 6. Рендер пошотово | рендер плана по утверждённому скелету; проверка: попало ли движение и сохранилось ли лицо |

## Слои

```
сценарий (план: действие, кто в кадре, ракурс, длительность)
   │
   ▼
1. КАСТИНГ ДВИЖЕНИЯ        какая запись и какой её отрезок играет этот план
   │                       (или «без референса» — для статики: дыхание, взгляд)
   ▼
2. ИЗВЛЕЧЕНИЕ              поза всего тела по кадрам (DWPose: тело, кисти, лицо),
   │                       трекинг людей, кто из них какой персонаж
   ▼
3. РЕТАРГЕТИНГ             — пропорции: скелет каждого персонажа приводится к его
   │                         росту и сложению (Август 1.78 м / 77 кг,
   │                         Адгар 2.05 м / 150 кг), стопы остаются на полу;
   │                       — камера: либо движение камеры оригинала (живой
   │                         оператор бесплатно), либо вертикальный рефрейм
   │                         9:16 с ведением как у оператора;
   │                       — время: 24 к/с, длина под сетку модели 17n+5,
   │                         без ускорения и замедления
   ▼
4. ГЕНЕРАЦИЯ               MiniMax H3 ref2va (лица, форма, площадка, звук — из наших
   │                       референсов) + Fun ControlNet Union 2.0 по позе
   ▼
5. ПРОВЕРКА                поза снимается с готового рендера и сравнивается со
                           скелетом (совпадение суставов по каждому персонажу);
                           сходство лица с референсом; прежний QA (камера, звук, бренды)
```

### Почему поза, а не глубина или контуры

ControlNet Union принимает позу, глубину, контуры, HED и другие сигналы.
- **Глубина и контуры** несут силуэт и сложение чужих бойцов, их клетку и рекламу. Модель перенесёт их тела, а не наши.
- **Поза** несёт только скелет. Тело, лицо и форму модель берёт из наших референсов.
- **Разница 77 против 150 кг** задаётся ретаргетингом скелета, а не силуэтом чужого тяжеловеса.

### Почему H3 + ControlNet, а не перенос движения на персонажа

| Кандидат | Что умеет | Почему не основной |
|---|---|---|
| **H3 ref2va + Fun ControlNet Union 2.0** | наши рефы лиц и площадки + поза + родной звук, та же модель, что во всех остальных планах | основной: единый вид и звук всего ролика. Совместимость ControlNet с ref2va не проверена |
| Wan 2.2 Animate (move/replace) | картинка персонажа + видео движения, один персонаж | запасной для планов с одним человеком; другая модель — другой вид, нет звука; в базе есть сообщение о дрейфе лица |
| Kling Motion Control | картинка + видео движения, API | запасной; в базе — дрейф лица и «плывущий» фон |
| Runway Act-Two | перенос игры на персонажа | только 720p, требует лицо в кадре весь план |
| Wan VACE | поза + рефы | статья: теряет лица при взаимодействии нескольких людей |

## Ограничения, которые архитектура ставит сценарию

1. **Контакт тел ретаргетинг ломает.** Если масштабировать скелет Августа, его руки перестают доставать до Адгара. Действия с захватом (клинч, борьба) либо без ретаргетинга (тогда рост одинаковый), либо не ставятся. **Твой сценарий — Адгар падает, не начав бой — контакта не требует. Это попадание.**
2. **Каждое действие с телом нуждается в записи.** Если записи нет, план либо статичный, либо снимаем своё движение на телефон.
3. **Ракурс записи = ракурс плана.** Скелет несёт перспективу камеры, на которую сняли запись. План, снятый «сверху», нельзя сыграть записью «снизу».

## Что нужно сценарию v2 от библиотеки движений (предварительно)

| Действие | Людей | Где взять запись |
|---|---|---|
| Выход в октагон, взгляд, дыхание | 1 | эфир (представление бойцов) |
| Стойка друг напротив друга, рефери между ними | 2–3, без контакта | эфир (рефери даёт команду) |
| Август машет перчаткой перед лицом | 1 + застывший | своя съёмка или эфир (жест рукой) |
| **Адгар «зависает» и падает плашмя** | 1 | недостача: в эфире нокауты, а не падение столбом. Варианты: стоковое падение, каскадёрское падение, своя съёмка на мат |
| Рефери останавливает бой | 1 | эфир (5:00–5:05 референса) |
| Рука победителя | 2 | эфир (5:54–5:58 референса) |

## Проба возможностей (стадия 4, до раскадровки)

Один вопрос — без его ответа архитектура не выбрана: **держит ли H3 ref2va наши лица и рост, если движение задаёт ControlNet по позе.**

- **План пробы:** падение Адгара из сценария — один человек, без контакта, ровно то, что нужно ролику.
- **Прогоны:** 3 по ~3–4 с:
  1. сила контроля 1.0;
  2. сила 0.7, контроль до 60 % шагов;
  3. без контроля, тот же сид — контроль.
- **Стоимость:** около 25 мин пода ≈ $0.9 (замер v1: ~60 GPU-с на секунду видео).
- **Что решает:**

| Исход | Решение |
|---|---|
| лицо и рост держатся, поза повторена | архитектура принята как есть |
| поза повторена, лицо уплыло | основная генерация H3, но для движущихся планов — перенос движения (Wan Animate) на наших персонажей; звук — из H3 |
| поза не повторена или граф не запускается | ControlNet к ref2va не подходит; планы с действием — через перенос движения на персонажа, остальное — H3 |

## Что уже готово с пробы, остановленной 2026-10-08

- Чекпоинт Fun ControlNet Union 2.0 скачан на постоянный том пода.
- Снятие позы (DWPose через rtmlib на GPU пода) работает: ~2 мин на клип, скелет чистый.
- Вертикальный рефрейм проверен на клинче. Клинча в сценарии нет, так что для ролика этот клип не нужен.
